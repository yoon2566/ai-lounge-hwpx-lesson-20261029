실습 준비

실습 폴더와 Codex 설정 준비하기

  1. 바탕화면에 ‘AI동아리실습’ 폴더를 만듭니다.
  2. Codex에서 프로젝트를 만들고 이 폴더를 연결합니다.
  3. 연결한 폴더가 바탕화면의 ‘AI동아리실습’인지 확인합니다.

HWPX 수정 스킬 준비하기

예시 프롬프트

skill-installer로 https://github.com/yoon2566/yoon_hwpx_3

이미 설치되어 있으면 확인만 해줘.

보이지 않으면 새 대화를 열거나 Codex를 재시작합니다.

실습 1 · 동아리 소개서

동아리 소개서 작성하기

동아리 소개서 양식 받기

  1. 소개서 파일을 Codex 입력창에 첨부하고 아래 요청을 보냅니다.
  2. 새 파일을 열어 가상 데이터와 표를 확인합니다.

예시 프롬프트

yoon-hwpx-3로 첨부한 HWPX 소개서에 가상 데이터를 채워줘.
우리동네 AI 배움동아리, 김영희 포함 8명, 월 2회·2시간이야.
AI로 생활문서를 배우고 이웃과 나누는 모임이야. 가상 장소는 이웃배움방이야.
나머지 항목도 가상 정보로 채우고 ‘교육용 가상 자료’라고 표시해줘.
원본과 표를 보존해 작업 폴더에 ‘작성완료_1_동아리소개서.hwpx’로 저장해줘.

실습 2 · 등록신청서와 회원명단

등록신청서와 회원명단 작성하기

② 동아리 등록신청서 받기

  1. 양식을 내려받아 Codex 입력창에 첨부하고 아래 요청을 보냅니다.
  2. 작성본에서 기본정보와 회원명단 8명을 확인합니다.

예시 프롬프트

yoon-hwpx-3로 첨부한 HWPX 등록신청서에 가상 데이터를 채워줘.
우리동네 AI 배움동아리, 김영희 포함 8명, 월 2회·2시간, 이웃배움방이야.
회원명단 8명을 가상 이름으로 채우고 앞 문서와 정보를 맞춰줘.
‘교육용 가상 자료’로 표시하고 연락처는 010-0000-0000, 서명은 비워줘.
원본과 표를 보존해 작업 폴더에 ‘작성완료_2_동아리등록신청서.hwpx’로 저장해줘.

가상 이름과 예시 연락처로 작성합니다. 실제 접수에는 기관의 정식 양식을 확인합니다.

실습 3 · 동아리 활동실적서

활동실적서에 내용과 사진 넣기

활동실적서 양식 · 사진 예제 2장

  1. 양식과 사진 2장을 내려받아 Codex 입력창에 함께 첨부합니다.
  2. 아래 요청을 보내고 작성본의 내용·사진·설명을 확인합니다.

예시 프롬프트

yoon-hwpx-3로 첨부한 HWPX 활동실적서에 가상 데이터를 채워줘.
우리동네 AI 배움동아리 8명이 이웃배움방에서 소개서와 등록신청서를 연습했어.
가상 활동일은 2026.11.5.와 11.19., 각 2시간이야. 내용도 가상으로 써줘.
첨부한 사진 2장과 설명을 넣고 ‘교육용 가상 활동·사진’으로 표시해줘.
원본과 표를 보존해 작업 폴더에 ‘작성완료_3_동아리활동실적서.hwpx’로 저장해줘.

사진 ZIP을 풀어 PNG 파일 2장을 첨부합니다. 교육용 가상 기록이며 실제 실적으로 제출하지 않습니다.

예시 프롬프트

‘이웃과 AI 배우기’: 김영희 등 8명, 2026.11.~12., 월 2회·2시간이야.
가상 장소는 이웃배움방이야. 생활문서·표·발표자료 배우기와 이웃 나눔을 계획해줘.
일정·역할도 가상으로 정하고 신청서와 맞춰 ‘교육용 가상 자료’로 표시해줘.
원본과 표를 보존해 작업 폴더에 ‘작성완료_5_사업계획서.hwpx’로 저장해줘.

신청서와 사업명·기간·인원을 같게 적습니다. 목표는 실제로 한 활동과 구분합니다.

실습 6 · 예산표

예산표 작성하기

⑥ 예산표 받기

  1. 양식을 내려받아 Codex 입력창에 첨부하고 아래 요청을 보냅니다.
  2. 합계가 4만원인지 확인하고 신청서 금액도 맞춥니다.

예시 프롬프트

yoon-hwpx-3로 첨부한 HWPX 예산표에 가상 데이터를 채워줘.
‘이웃과 AI 배우기’의 교재 5,000원×8권, 지원금 4만원·자체부담 0원이야.
나머지 비용은 0원으로 쓰고 계산 근거와 합계를 채워 신청서 금액과 맞춰줘.
‘교육용 가상 예산’으로 표시하고 실제 지원 가능 여부는 별도 확인으로 적어줘.
원본과 표를 보존해 작업 폴더에 ‘작성완료_6_예산표.hwpx’로 저장해줘.

총사업비 = 지원금 + 자체부담. 자동 합계 수식이 없어 직접 계산해 대조합니다.
가상 예산으로 연습하고, 신청서의 금액도 맞춥니다.

실습 마무리

문서 6개 함께 확인하기

  1. 동아리명, 사업명, 기간, 인원이 문서마다 같은지 봅니다.
  2. 예산표 합계와 신청서의 지원신청액을 비교합니다.
  3. Codex에 파일 검사와 내용 비교를 요청합니다.
  4. 작성본을 한글에서 다시 열고 표·사진·페이지를 확인합니다.

예시 프롬프트

yoon-hwpx-3로 작업 폴더의 ‘작성완료_1_’부터 ‘작성완료_6_’까지 문서를 검사해줘.
동아리명·사업명·인원·기간·금액의 불일치와 빈칸을 알려줘.
원본은 바꾸지 말고 ‘검사결과.txt’로 저장해줘.

파일 검사 통과만으로 실제 한글 화면까지 정상이라고 판단하지 않습니다.

현재 Codex에서 선택한 작업 폴더를 사용합니다.

더 해보기 · 실제 공고와 공식 문서

원본을 남기고 HWPX로 변환하기

  1. Codex 입력창에 변환할 HWP 파일을 첨부합니다.
  2. 아래 프롬프트로 작업 폴더에 HWPX 변환본을 만듭니다.
  3. 이름 앞에 ‘변환_’이 붙은 새 파일을 확인합니다.

예시 프롬프트

rhwp를 이용해 첨부한 HWP 파일을 HWPX로 변환해줘.
원본은 그대로 두고, 파일 이름 앞에 ‘변환_’을 붙여
현재 작업 폴더에 저장해줘.
변환 전후 내용·쪽 수·배치 차이도 확인해줘.

파일 이름의 확장자만 바꾸지 않습니다. 공식 원본은 조사·변환 체험용입니다.

더 해보기 · 실제 공고와 공식 문서

변환 전후를 눈으로 확인하기

  1. 원본 HWP와 변환한 HWPX 파일을 각각 엽니다.
  2. 두 문서를 나란히 놓고 제목, 본문, 표와 사진을 살펴봅니다.
  3. 빠진 내용, 잘린 표, 줄바꿈과 쪽 수가 달라진 곳을 확인합니다.

파일이 만들어졌는지만 보지 않고, 문서 화면을 직접 확인합니다.

완성한 HTML을 로컬 서버로 실행하고 브라우저에서 볼 수 있는 접속 주소를 알려줘.

실행 후 Codex가 알려 준 실제 접속 주소를 엽니다. 디자인 PNG를 통째로 붙이는 방식이 아닙니다.

실습 6 · 브라우저 확인

문구·순서·배치 수정하기

접속 주소를 열어 8페이지를 넘겨 보고, 고칠 페이지를 정합니다.

예시 프롬프트 · Codex

브라우저에서 보니 4페이지 본문이 길어.
핵심 뜻을 유지하며 두 문장으로 줄이고 제목 아래 여백을 넓혀줘.
5페이지와 6페이지의 순서를 바꿔줘.
‘발표_디자인.png’의 색상·글꼴·배치는 유지해줘.
수정한 페이지를 브라우저에서 확인하고 접속 주소를 다시 알려줘.

HTML은 필요한 문구와 배치만 빠르게 고칠 수 있습니다.
매번 이미지 전체를 다시 생성하는 시간과 사용량을 줄일 수 있습니다.

실제 시간·사용량은 수정 범위와 도구에 따라 달라집니다. 비용 절감을 보장하지는 않습니다.

실습 7 · 최종 확정

발표 내용과 화면 확정하기

  1. 8페이지를 순서대로 읽으며 5분 발표를 연습합니다.
  2. 빠진 내용·오탈자·잘림과 원래 디자인의 일관성을 확인합니다.
  3. 최종 HTML과 페이지별 확정 원고를 작업 폴더에 남깁니다.

예시 프롬프트 · Codex

지금 HTML의 내용과 순서를 최종안으로 정할게.
각 페이지의 제목·본문을 그대로 뽑아 ‘최종원고.txt’로 저장해줘.
페이지 번호와 디자인 유형도 적고, 원문을 요약하거나 새로 쓰지 말아줘.
HTML과 연결된 파일을 작업 폴더에 함께 보관해줘.

다음 이미지 제작에서도 이 확정 원고와 HTML 화면을 기준으로 사용합니다.

실습 8 · Template Creator

미리보기 PNG를 이미지 템플릿으로

Codex에서 만든 ‘발표_디자인.png’ 한 장을 첨부합니다.
Template Creator를 선택해 개인 이미지 템플릿으로 등록합니다.

예시 프롬프트 · Codex

Template Creator로 첨부 PNG 한 장을 재사용할 이미지 템플릿으로 등록해줘.
표시 이름은 ‘데이터 센터 발표’로 해줘.
imagegen용이며 네 화면의 색상·글꼴·배치와 16:9 비율을 참고하게 해줘.
사용할 때는 해당 페이지 유형 하나만 한 장에 만들도록 해줘.
등록이 끝나면 템플릿 카드와 실제 스킬 이름, 사용 방법을 알려줘.

등록 완료 카드가 나와야 완료입니다. PNG를 첨부하거나 이름만 정한 것으로 등록되지 않습니다.
이 템플릿은 개인 스킬로 보관되며, 새 플러그인을 배포하는 과정이 아닙니다.

실습 9 · 이미지 젠

등록 템플릿으로 첫 장 만들기

imagegen을 선택해 템플릿 갤러리에서 ‘데이터 센터 발표’를 고릅니다.
또는 등록 때 안내된 실제 스킬을 선택합니다.

예시 프롬프트 · 템플릿을 선택한 뒤

선택한 이미지 템플릿과 작업 폴더의 최종원고.txt·HTML을 참고해줘.
확정된 HTML의 1페이지 화면도 확인해줘.
imagegen으로 1페이지 제목 슬라이드 이미지를 16:9로 만들어줘.
제목과 본문은 최종원고 그대로 쓰고 요약하거나 추가하지 말아줘.
2×2 미리보기 대신 제목 페이지 한 장만 생성해줘.
작업 폴더에 ‘최종슬라이드_01.png’로 저장해줘.

HTML 캡처는 화면 참고 자료이고, 최종 결과는 이미지 젠으로 새로 생성한 이미지입니다.

실습 10 · 페이지별 이미지 제작

나머지 페이지도 한 장씩 만들기

첫 장의 디자인과 문구를 확인한 뒤 같은 템플릿을 다시 선택합니다.

예시 프롬프트 · Codex

같은 등록 이미지 템플릿으로 2~8페이지를 imagegen으로 만들어줘.
최종 HTML의 각 페이지 내용·화면과 최종원고.txt를 함께 참고해줘.
목차·챕터 카드·내용에 맞는 디자인 유형을 적용해줘.
제목·본문을 그대로 유지하고 각 페이지를 별도 16:9 PNG로 생성해줘.
HTML 캡처를 최종 이미지로 대신하지 말고, 여러 페이지를 한 장에 합치지 말아줘.
작업 폴더에 ‘최종슬라이드_02.png’부터 ‘최종슬라이드_08.png’로 저장해줘.

한 번에 모두 생성되지 않으면 남은 페이지 번호를 지정해 이어서 요청합니다.

결과 확인

최종 이미지의 글자와 숫자 확인하기

  1. PNG 8장을 열어 순서와 각 이미지의 16:9 비율을 확인합니다.
  2. HTML·최종원고와 대조해 글자·숫자·빠진 문장을 검사합니다.
  3. 발표 화면 크기에서 가독성·잘림·여백을 확인합니다.

오류가 있는 페이지 수정 예시 · Codex

최종슬라이드_04.png의 본문에 오탈자가 있어.
최종원고.txt의 해당 페이지 제목과 본문을 그대로 사용해줘.
imagegen으로 그 페이지만 수정하고 템플릿 디자인과 16:9를 유지해줘.
작업 폴더에 ‘최종슬라이드_04_수정.png’로 저장해줘.

결과물 · 수정 가능한 HTML, 최종원고 TXT, 등록한 이미지 템플릿, 페이지별 PNG 8장
이미지 생성은 글자를 바꿀 수 있으므로 수정한 이미지도 다시 검수합니다.
